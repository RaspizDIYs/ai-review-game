# Как писать задачи

Одна задача — один файл `tasks/<id>.json`. Имя файла обязано совпадать с `id`.
Сборка `npm run pack` превращает их в `src/content/pack.json`, который читает игра.

Главное отличие авторского формата от игрового: **подлянка указывается куском кода,
а не номером строки**. Номера разъезжаются от любой правки дифа и молча начинают
указывать не туда; кусок кода правку переживает, а если стал неоднозначным —
сборка падает и скажет, на каких строках он встретился.

```bash
npm run pack     # собрать пак
npm run check    # собрать + типы + тесты + валидация
```

## Шесть шагов

1. **Взять подлянку** из «Колоды подлянок ИИ в коде» или новую — но такую,
   при которой код собирается и тесты проходят. Если она валит CI, это не наша игра.
2. **Придумать запрос к ИИ**, при котором она возникает естественно. Пишется живым
   языком, так, как просят в реальности: «добавь кэш, а то дёргаем базу на каждый чих».
3. **Написать диф так, чтобы он выглядел нормальной работой.** Подлянка не должна
   быть единственным изменением — иначе её видно по объёму, а не по смыслу.
4. **Написать зелёный прогон тестов, который её не ловит.** Это самая ценная часть
   и её проще всего сделать неубедительно. Проверь себя: сможешь одной фразой
   сказать, *почему* тест врёт? «Проверяет запись, а не чтение», «гоняет happy path»,
   «фикстуры не задевают границу». Если фразы нет — задача сырая.
5. **Добавить одну-две обманки**: строки, к которым справедливо придраться,
   но которые не являются подлянкой. Для чистых задач обманки обязательны,
   и чем их больше, тем раунд ценнее.
6. **Отдать второму человеку.** Не нашёл за 90 секунд — слишком сложно,
   нашёл за 10 — слишком легко. Только после этого заполняются
   `verified_by` и `verified_at`.

## Поля

| Поле | Что это |
|---|---|
| `id` | `<стек>-<тема>-<номер>`, навсегда: по нему лежит история в localStorage |
| `stack` | `js`, `py`, `sql`, `cs`, `go`, `rs`, `java`, `php`, `cpp`, `rb`, `swift`, `sh` — он же язык подсветки; полный список в `LANG` из `scripts/highlight.mjs` |
| `difficulty` | 1–5, см. таблицу в ТЗ |
| `prompt` | что «попросили у ИИ» |
| `tests` | вывод прогона, **всегда зелёный** |
| `diff` | unified diff, ровно то, что увидит игрок |
| `clean` | `true` — подлянки нет, правильный ответ «здесь чисто» |
| `bugs[].match` | кусок кода из строки с подлянкой, уникальный в пределах дифа |
| `bugs[].kind` | `wrong` — код неверен, нужно точное попадание. `missing` — кода не хватает, засчитывается ±1 строка |
| `bugs[].explain` | что не так |
| `bugs[].consequence` | **что сломается, у кого и когда.** Важнее, чем explain: что не так, игрок обычно понимает сам, а запомнит он последствие. «Будут проблемы» не годится |
| `decoys[].match` | кусок кода обманки |
| `decoys[].why` | почему к ней справедливо придраться и почему это всё-таки не она |

## Грабли

**Обманка не должна стоять вплотную к подлянке типа `missing`** — у неё допуск ±1
строка, и обманка попадёт в засчитанные. Тест это ловит, но лучше сразу разносить.

**`match` должен быть уникален** среди строк новой версии файла. Строку вида `}`
или `  return` матчить бесполезно — бери кусок подлиннее.

**`match` — это одна строка.** Многострочный кусок (например, пустой `catch`
из трёх строк) не найдётся вовсе: сборка ищет построчно. Указывай ту строку,
по которой игрок должен кликнуть.

**Формулировку причины** для нового тега добавляй в `content/reasons.json` —
без неё пак не соберётся. Это то, что игрок выбирает на шаге «почему»,
поэтому она должна быть неотличима по тону и длине от чужих: иначе правильный
вариант виден без чтения кода.

**Зелёный прогон пишется на языке задачи.** Валидатор ищет признаки красного
(`FAIL`, `2 errors`, `Failures: 1`), а не слово «failed»: у .NET, JUnit и cargo
зелёный отчёт сам печатает «Failures: 0».

**Пустую строку сматчить нельзя.** Если якорь приходится на пустую строку,
двигай его на соседнюю осмысленную.

**Чистые задачи почти всегда сложные** (у нас все на 4–5) — и это правильно.
Последний слот дневной серии как раз хочет сложность 4, а чистый раунд на единичке
разгадывается мгновенно.

## Черновик через ЛЛМ

```bash
node scripts/draft-task.mjs js cache-invalidation 3
```

Печатает готовый промпт — его отдаёшь модели, ответ кладёшь в `content/tasks/`.
Модель работает **на авторинге, а не в рантайме**: в игре её нет и не будет,
иначе не получится ни общего сида, ни воспроизводимости, ни доверия к вердикту.
Всё, что она нагенерила, всё равно проходит шаги 4–6 руками.
