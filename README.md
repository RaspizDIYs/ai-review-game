# Ревью за ИИ

ИИ написала код. Он собирается, тесты зелёные. Найди, где тебя обманули — за 90 секунд.

Игра из брейншторма со Шпинатом. Полное ТЗ, задачи и обоснования решений живут
в общем Obsidian-хранилище `goodluck`: заметки `ТЗ — Ревью за ИИ`,
`Формат задачи — Ревью за ИИ`, `Задачи — Ревью за ИИ`.
**Правила ведения проекта — заметка `Как вести проекты`, прочитай её до первой правки.**

### Режимы

| Режим | Что это | Что настраивается перед началом |
|---|---|---|
| **Дневной челлендж** | 5 раундов, у всех одинаковые, меняются в 00:00 UTC. Один заход в день, результат шерится строкой 🟩🟥⬜ | ничего — на то и челлендж |
| **Ночное дежурство** | играешь, пока не пропустишь три подлянки | уровень (потолок сложности) и языки |
| **Своя подборка** | три задачи под уровень и языки, каждая следующая другая | уровень и языки |
| **Смена** | 14 ходов вслепую, прод копит баги и может упасть | свой стек: фронт + бэкенд + пайплайн, без потолка сложности |

Первые три — тренировка: после каждого раунда показывают разбор.
Смена — работа: вердикта нет, единственный источник правды — прод.

### Смена, если коротко

Пропущенная подлянка не наказывает сразу — она ложится в прод скрытой миной
с фитилём на 2–6 ходов. Догорел — прод падает и **будет падать каждый ход**,
пока причину не найдут. Найти можно только руками: открыть свой же мёрдж
заново и разметить строку. Попал — мины нет, промахнулся — осталась, полез
в чистый PR — сломал его сам.

Чинить можно на падении и между сменами, во время смены — нет.
Три заряда уборки на смену закрывают по одной тихой мине наверняка.

Прод переносится в следующую смену. Упал — игра кончена, и вот тогда
показывают полный разбор: по каждому PR видно, что в нём было на самом деле.

```bash
node -e "const p=require('./src/content/pack.json');const l=require('./src/content/incidents.json');const s={};for(const t of p)s[t.stack]=(s[t.stack]||0)+1;const g=new Set(p.flatMap(t=>t.bugs.map(b=>b.tag)));console.log(p.length,'задач ·',Object.keys(s).length,'языков ·',g.size,'тегов ·',l.length,'логов')"
```

Локально:


## Выкладка

Игра статическая, поэтому хостится где угодно.

**GitHub Pages** — основной вариант, выкладывается сам на каждый push в `main`
(`.github/workflows/pages.yml`). Перед выкладкой гоняется `npm run check`,
так что битая задача до прода не доедет.

**Свой сервер с Traefik** — если хочется рядом с остальным:

```bash
HOST=myserver ./deploy/deploy.sh
```

Домен задаётся на сервере, в `<каталог>/.env` → `DOMAIN=...`, дальше
`docker compose up -d`. Контейнер ест 3–4 МБ памяти.

Адрес сайта для og-превью — в `.env` (`VITE_SITE_URL`). Он нужен только
для картинки в превью ссылки: краулеры не разворачивают относительные пути.

## Как запустить после клона

Нужен только Node 22+ (разрабатывается на 26) и npm. Ничего больше:
ни базы, ни бэкенда, ни ключей — см. решение «Бэкенда в MVP нет».

```bash
npm install     # зависимости
npm run dev     # дев-сервер
npm run check   # типы + тесты + валидация пака, гонять перед каждым коммитом
npm run build   # прод-сборка в dist/, это статика, её можно просто положить на диск
```

## Добавить задачу

Пак — это и есть игра, поэтому добавлять задачи должно быть просто.

```bash
npm run new-task js race-condition 4   # заготовка content/tasks/js-race-condition-001.json
npm run draft    js race-condition 4   # промпт для черновика через модель
npm run check                          # собрать, проверить типы, тесты и пак
```

Заготовка сразу роняет `npm run check` — в ней остались `TODO`, и валидатор считает
это ошибкой. Так недописанная задача не уедет в игру незаметно.

Правила, поля и грабли — в [content/README.md](content/README.md).
На пул-реквест то же самое гоняет CI.

## Оболочка

Интерфейс собран по макету «Ревью за ИИ — игровая оболочка». Что из этого
важно знать при правках:

- **Акцент — не константа.** Внутри раунда интерфейс красится в цвет агента,
  который «написал» код, снаружи — в цвет агента, выбранного на главной.
  Кнопки, чекбоксы, полосы и свечения берут цвет пропсом, а не из темы
- **Агенты** (`src/agents.ts`) — четыре персоны с репликами на брифинге
  и после вердикта. Портреты лежат в `public/agents/<slug>.png`; нет файла —
  рисуется монограмма, вёрстка не разъезжается. Оригиналы — в `content/agents/`,
  оттуда их подгоняет `npm run avatars`: скрипт находит на картинке настоящий
  круг и вырезает описанный вокруг него квадрат, иначе круглая маска вёрстки
  садится мимо рисунка и сбоку остаётся чёрный серп
- **Пул-реквест** (`src/pr.ts`) — заголовок, ветка и метки собираются
  из самой задачи: тип по глаголу из запроса к ИИ, область по файлу из дифа.
  Имя репозитория правится прямо в шапке (`src/components/RepoName.tsx`):
  клик по названию — и это поле ввода. Оно же уезжает в брифинг
- **Ачивки и ранги** (`src/achievements.ts`, `src/ranks.ts`) считаются
  из настоящей игры и лежат в localStorage вместе с прогрессом. Три этажа:
  языковые (по одной на стек, у них вместо иконки код языка), счётчики
  пойманных подлянок и труднодостижимые — все языки, все ачивки, десять
  находок подряд. Последние два считаются от остального списка
  (`derivedUnlocks`), поэтому выдаются вторым проходом, уже после раунда
- **Узкий экран.** Колонка своей подборки уезжает в шторку под шестерёнкой
  в шапке, регулятор звука разворачивается столбиком под кнопкой, а лента
  ачивок листается пальцем — кнопка «все ачивки» при этом стоит под лентой,
  а не в её конце, иначе до неё не долистать
- **Звук** (`src/sound.ts`) — тона на WebAudio, без единого файла.
  Выключается в шапке, состояние запоминается
- **Музыка** (`src/music.ts`) — две темы из `public/music/`, крутятся по кругу
  в одном `<audio>`. Громкость — ползунок, который кнопка громкости в шапке
  раскрывает вправо. Автостарт висит на первом касании страницы: до него
  браузер `play()` не пропускает
- **Иконки** (`src/ui/icons.tsx`) — инлайновые svg в наборе Lucide.
  Часть путей взята из макета, остальные дорисованы вручную
- **Шрифты** — Unbounded, Golos Text и JetBrains Mono с Google Fonts.
  Без сети страница отрисуется системными: макет от этого просядет,
  но игра работает

## Архитектура

Статический фронтенд, никакого сервера:

- **React 19 + TypeScript + Vite 8**, стили — Tailwind 4
- **контент** — `src/content/pack.json`, формат описан в заметке
  «Формат задачи — Ревью за ИИ» и продублирован типами в `src/types.ts`.
  Подсветка лежит отдельно, по файлу на задачу (`src/content/tokens/<id>.json`),
  и подтягивается только для той задачи, что на экране: в паке она весила
  три четверти веса и ехала в первый бандл целиком
- **`src/diff.ts`** — свой парсер unified diff. Библиотеку не берём: нужен клик
  по конкретной строке и её номер в новой версии файла, по которому размечены подлянки
- **`src/scoring.ts`** — очки и проверка ответа. Подлянки бывают двух видов:
  `wrong` (код на строке неверен, нужно точное попадание) и `missing`
  (кода не хватает, засчитывается ±1 строка)
- **`src/round.ts`** — разрешение хода: засчитан ответ или нет. Вынесено
  из компонента специально, чтобы проверяться тестами, а не кликами
- **`src/reason.ts`** — шаг «почему»: нашёл строку → выбери из четырёх, что
  с ней не так. Варианты детерминированы от id задачи, отвлекающие берутся
  из тегов того же стека, формулировки — `content/reasons.json`. Не угадал
  причину — очки за раунд вполовину, но раунд остаётся выигранным
- **`src/levels.ts`** — уровень проверяющего и своя подборка. Уровень
  (Стажёр — Джун — Мидл — Сеньор) это потолок сложности, а не рейтинг игрока:
  человек сам говорит, на что подписывается. Подборка — три задачи под уровень
  и выбранные языки, детерминирована от сида; счётчик сыгранных входит в сид,
  иначе «собрать ещё одну» отдавало бы ту же тройку
- **`src/stacks.ts`** — подписи языков и порядок в списке. Список стеков
  на стороне сборки живёт в `LANG` из `scripts/highlight.mjs`: по нему же
  валидатор проверяет префикс id, а `new-task` решает, что можно создать
- **`src/daily.ts`** — выбор задач дня. Полностью детерминирован от даты
  (FNV-1a от `YYYY-MM-DD` в UTC), поэтому серия одинаковая у всех и без сервера.
  Задачи разложены в «колоду» на каждую сложность: день берёт элемент по номеру дня,
  так что повтор возможен не раньше полного круга — и круг удлиняется сам,
  когда в пак добавляют задачи
- **`src/storage.ts`** — прогресс в localStorage: заходы по дням, серия дней подряд,
  рекорд бесконечного режима и незаконченная серия. Последняя пишется после
  каждого вердикта: упавшая вкладка не должна съедать единственный за день заход
  и не должна давать начать его заново
- **`src/share.ts`** — строка результата 🟩🟥⬜, без кода и названий задач
- **`src/App.tsx`** — экраны. В тренировочных режимах
  `home → setup → briefing → review → reason → verdict → summary`,
  в смене вердикта и шага «почему» нет:
  `briefing → review → (incident) → repair → shift-end → postmortem`

### Смена

Отдельный слой поверх раунда, см. заметки `Дополнение — Ревью за ИИ`
и `Слепая смена — Ревью за ИИ`:

- **`src/defects.ts`** — скрытые дефекты: рождение из пропуска, фитиль, утечка,
  состояния «тихий» и «упавший». Всё детерминировано хэшем от id задачи
  и номера PR: случайности нет, иначе разбор в конце нечем объяснить
- **`src/prod.ts`** — три шкалы: здоровье, долг (считается из дефектов,
  отдельно не хранится) и скорость команды. Скорость нужна обязательно,
  иначе выигрышная стратегия — блокировать всё подряд
- **`src/shift.ts`** — сама смена: ход, порядок «действие → тик → новый дефект»,
  починка руками, уборка, конец смены. Чистые функции, проверяются тестами
- **`src/incident.ts`** — лог инцидента по тегу подлянки и подозреваемые
- **`npm run sim`** — модель игрока на 400 смен. Метрик с людей нет и не будет,
  поэтому баланс проверяется так: ловит заведомо сломанное правило до того,
  как в него кто-то сыграет

## Для разработчика

**Номера строк в паке — это номера в новой версии файла**, той, что справа в дифе.
Удалённые строки номера не имеют и не кликаются. Проще всего ошибиться именно здесь,
поэтому:

- `npm run validate` проверяет, что каждая размеченная строка реально существует
  в дифе, что у чистых задач нет подлянок, а прогон тестов зелёный
- `npm test` дополнительно проверяет, что подлянка засчитывается, а обманка — нет,
  и что допуск ±1 работает только для `missing`

Валидатор и игра используют **один и тот же парсер**, так что «строка 16» в паке
и «строка 16» на экране — это гарантированно одна строка.

**Пак генерируется, `src/content/pack.json` руками не правим** — правим
`content/tasks/*.json`, дальше `npm run pack`. Он же раскладывает подсветку
Shiki по `src/content/tokens/` — этот каталог пересобирается целиком, класть
туда что-то своё бессмысленно.

**Клавиатура:** ↑/↓ ведут по строкам дифа, Enter выбирает, C — «здесь чисто».
Enter намеренно не висит глобальным обработчиком: то же нажатие, которым
выбрали строку, долетало бы до окна уже на вердикте и проматывало разбор.
На вердикте кнопка «дальше» просто получает фокус.

**Относительные импорты пишем с расширением** (`./daily.ts`). Vite проглатывает
и без него, а Node в тестах — нет, и падает это только когда модуль впервые
затянут тестом, то есть далеко от места правки.

Добавляешь задачу — гоняй `npm run check`. Задача без `verified_by` попадает
в предупреждения: в пак идут только проверенные вторым человеком.

## Известные ограничения

**Ни у одной задачи не проставлен `verified_by`.** По нашему правилу в пак идёт
только проверенное вторым человеком, так что валидатор о них предупреждает.
Пока это предупреждение, а не ошибка — станет ошибкой, когда пак проверят.

**Сложность откалибрована на глаз.** Без бэкенда нет статистики «сколько процентов
нашли», поэтому цифра 1–5 у задачи — это мнение автора, а не измерение.
Калибровка руками на пятерых знакомых — отдельная задача.

**Колоды по сложности пока короткие.** Задач сложности 1 всего две, то есть первый
раунд повторяется через день. `npm run validate` показывает длину круга по каждой
сложности — растить пак стоит по этому списку, а не наугад.

**Метрики адресные, а не общие.** Собираем только то, что меняет решения
по контенту: id задачи, исход, секунды, попытка, режим. Ни кук, ни идентификатора
игрока, ни IP — сервер его не пишет, поэтому события нельзя склеить в сессию
и нельзя посчитать «уникальных пользователей». Это осознанная плата.
Адрес не задан (`VITE_METRICS_URL` пустой) — не уходит ничего.

Отчёт: `HOST=myserver node scripts/metrics.mjs`. Главная колонка — «нашли»:
меньше 20% значит задача непонятная, больше 80% быстрее 15 секунд — слишком
лёгкая, много ложных обвинений на грязной задаче — обманка сильнее подлянки.
